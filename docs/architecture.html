Data Flow — Dashboard Request

User navigates to /

main.js mounts App.vue; Vue Router resolves the root path to views/Dashboard.vue.

Dashboard reads current filters

The view calls useFilters().getCurrentFilters() — a singleton composable holding four refs (period, location, category, status) — and maps them to API param names (month, warehouse, category, status).

API call via src/api.js

Axios issues GET http://localhost:8001/api/dashboard/summary?warehouse=…&category=…&status=…&month=…. The same client wraps every endpoint as a function — UI code never touches URLs directly.

FastAPI handler runs

server/main.py applies apply_filters() to inventory and orders, then filter_by_month() for time-period (supports both 2025-01 and Q1-2025). Aggregates inventory value, low-stock count, pending orders, backlog count, and order revenue.

Pydantic validates & serializes

Response is shaped through Pydantic models (InventoryItem, Order, …) and returned as JSON.

Dashboard renders

Raw payload lands in refs; KPI cards and SVG charts are computed derivations. Changing any filter in FilterBar.vue mutates the shared refs, every view watching them re-fetches automatically.

Notable Patterns

Singleton filter composable

Four refs (period, location, category, status) live inside useFilters() at module scope. Every view that imports it sees the same instance, so FilterBar.vue changes propagate without prop drilling or a store.

Server-side filtering only

The Vue layer does not filter lists itself — it forwards filter values as query params and re-renders whatever the API returns. Keeps the client thin and the API behavior testable.

JSON fixtures as the database

mock_data.py loads seven JSON files once at startup; everything runs against in-memory dicts. Restarting the server discards any runtime mutations (e.g. created purchase orders).

Custom SVG charts

No charting library. Each view renders its charts as inline SVG built from computed() data — predictable, dependency-free, easy to style.

Pydantic at the boundary

Every endpoint declares a response_model. The JSON shape and the typed contract live in the same file (server/main.py), so schema drift fails fast.

Centralised API client

client/src/api.js maps 1:1 to the FastAPI surface. UI code calls api.getDashboardSummary(filters) rather than constructing URLs — one place to change base URL, auth, or error handling.
